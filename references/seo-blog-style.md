# SEO 博客适配器

SEO 博客首先要让带着搜索问题进入页面的人完成任务，其次才是帮助搜索引擎理解页面。不要把关键词密度、固定篇幅、固定 FAQ 数量或标题配额当作质量规则。

## 先锁定搜索任务

一篇文章只选一个主意图：了解、诊断、比较决策、实施前评估或产品选型。记录读者已经知道什么、希望完成什么、读完后不应再搜索什么。

按意图选择原型：

- 常青指南：直接答案 → 必要概念 → 方法/模型 → 边界 → 下一步。
- 比较决策：选择标准 → 方案差异 → 适用条件 → 决策表 → 验证方式。
- 诊断文章：症状 → 指标分解 → 原因树 → 排查顺序 → 预防与监控。
- 实施前评估：前提 → 资源/成本模型 → 试点步骤 → 风险与回退。

这四条不是固定目录。缺少内容时删节，复杂时增加真正需要的 H3。

## 页面级输出

根据 CMS 能力在 frontmatter 或单独的 `seo-meta.md` 中提供：

```yaml
title: 页面唯一标题
description: 一到两句准确摘要
slug: readable-slug
primary_intent: decision
canonical: 待发布 URL 或留空
```

不要生成 `meta keywords` 作为排名手段。标题、description、H1 和正文必须承诺同一件事，且不夸大结果。

## 正文结构

- H1 只有一个，准确描述页面答案。
- 开头尽早给短答案和适用边界，不先堆行业背景。
- H2 覆盖完成搜索任务所需的主要子问题；H3 用于一个子问题下的步骤、原因或方案。
- 标题层级连续。标题数量由信息关系决定，不为 SEO 凑数。
- 摘要框、表格、清单、FAQ 和代码都是条件组件，不是强制组件。

步骤、优先级和判断顺序优先使用有序列表。无序列表只放真正平级且顺序无意义的项目，并保持克制；若每个项目都需要解释，改写成带小标题的自然段。不要为了让页面“看起来结构化”而在每个 H2 下放一组圆点。

FAQ 只有在搜索结果、站内搜索、客服记录或用户材料确实显示存在独立长尾问题时才添加。答案必须自包含，但不限制为固定 5 个，也不重复正文换词。

## 关键词与链接

主关键词自然出现在页面标题、开头答案以及至少一个真正相关的标题中即可。使用读者会用的近义词和技术实体覆盖问题，不追求固定密度。

- 内链帮助读者补背景、继续实施或进入合理的产品决策。
- 外链在声明附近连接可靠的一手来源。
- 锚文本说明目标页内容，不连续重复精准商业词。
- 需要商业转化时，让 CTA 对齐当前意图：了解型给延伸资料，决策型给试用/评估，实施型给文档。不要每节插 CTA。

## 99CDN 植入

先建立方案选择标准，再把 99CDN 映射到可证实的能力和页面。单独产品段落可以存在，但必须回答“它在当前决策中承担什么角色”，并给替代路径、限制或验证动作。产品事实用当前官方来源，第三方结论不能只靠官网自证。

## 自然表达门

SEO 结构不能接管中文表达。搜索意图决定需要回答什么，不决定每段必须采用相同句型。

1. 每个主要判断至少连接一个已核验事实、具体机制、可执行步骤或明确限制。
2. 不用“拆账单、打通链路、跑通闭环、赋能、抓手”等压缩词代替正常解释。
3. 删除没有信息增量的“值得注意的是、在一定程度上、随着行业发展、由此可见”。
4. 避免一连串名词和“的”字修饰；优先写清谁做什么、数据怎样变化、读者下一步检查什么。
5. 可以比知乎更利于扫描，但不能变成定义、列表、总结循环出现的资料页。
6. 引用放在对应事实附近。来源列表、FAQ 或结尾链接不能替代正文中的证据连接。

## People-first 审核

- 页面是否增加了自己的模型、分析或决策方法，而不只是改写搜索结果？
- 读者是否能完成标题承诺，不必回到搜索页补关键步骤？
- 作者、来源、更新时间和内容生成方式是否在需要时可解释？
- 是否为了长度、关键词或 FAQ 配额写了无价值段落？
- 广告与链接是否干扰主要阅读任务？
