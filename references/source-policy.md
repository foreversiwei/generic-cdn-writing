# 来源与样本政策

## 五层语料

| 层级 | 用途 | 可以证明 | 不可以证明 |
|---|---|---|---|
| 产品官方事实 | 官网、帮助文档、价格页、公告 | 当前公开功能、配置、版本、官方声明 | 独立性能、真实节省、客户满意度 |
| 第三方体验 | 独立教程、实测、论坛讨论 | 作者实际观察和具体环境结果 | 普遍性能、所有版本结论 |
| 通用技术证据 | RFC、软件官方文档、工程博客、论文 | CDN、缓存、DNS、回源等机制 | 99CDN 已实现或达到相同性能 |
| 知乎文风样本 | 高质量技术文章、回答 | 结构、节奏、读者问题和表达方式 | 产品与技术事实 |
| SEO 搜索样本 | 当前搜索结果、相关问题、竞品页面 | 搜索意图、内容缺口、常用术语 | 真实性和权威性 |

## 可信等级

- `A`：当前官方原始资料、标准、原始数据或可复现实验。
- `B`：署名清晰、过程具体的工程文章或第三方实测。
- `C`：有来源但缺少完整方法、可能带商业目的的教程或评论。
- `D`：聚合转载、无作者无日期、明显 SEO 拼接或无法追溯内容。

关键产品事实优先使用 A；第三方评价至少标记 B/C 和环境边界。D 级只能用于发现关键词，不能进入事实论证。

## 声明账本

写作前建立声明表：

| Claim | Evidence | Verdict | Notes |
|---|---|---|---|
| 文章准备表达的具体事实 | URL 与页面位置 | 已支持 / 部分支持 / 推断 / 缺少证据 | 时间、版本、环境、限制 |

以下内容必须单独核验：价格、免费额度、节点限制、协议与架构支持、性能数字、节省比例、并发、缓存命中率、回本周期、客户案例和发布日期。

产品官网的“降低成本”“提高性能”属于厂商声明。若没有独立测量，正文应写成“官网称”“设计目标是”或“理论上可通过……影响成本”，不得写成已被独立验证的结果。

## 逐论点审计规则

大纲中的每个外部可核验事实都必须拥有唯一 Claim ID。一个来源可以支持多条声明，但每条声明都要单独填写页面位置和实际支持范围，不能用“来源相同”跳过核验。

声明类型与最低证据要求：

1. 产品能力、价格和版本：需要当前官方原始页面；价格和版本必须记录访问日期。
2. CDN、缓存、DNS、回源等机制：优先标准、软件官方文档或过程完整的工程资料。
3. 性能、节省比例、回本周期和容量结果：需要用户原始数据或方法透明的独立测试；产品官网不能单独证明。
4. 第三方体验：只能证明作者在明确环境中的观察，不能直接外推到所有网站。
5. 分析和建议：必须能指出依赖哪些已核验事实，并明确这是推断而不是来源原话。

运行 `scripts/audit_claims.py` 后，先向用户展示每条声明的 `use / qualify / omit` 决策。未经用户确认的声明审计不能进入正文。

## 搜集与去重

1. 为每个主题同时设计产品词、机制词、问题词和相邻词查询。
2. 保存 canonical URL、标题、域名、日期、作者和正文快照哈希。
3. 去掉 `utm_*`、`ref`、`source` 等追踪参数和 URL 片段。
4. 标记全文或段落高度相似的转载；同一原稿只算一个独立样本。
5. 同域大量近似文章不能充当多个独立证据。
6. 记录访问日期；动态产品事实发布前重新打开当前页面。

可以用 `scripts/build_source_cards.py` 从 Markdown 素材包提取、规范化并去重链接：

```powershell
python scripts/build_source_cards.py source-pack.md `
  --official-domain 99cdn.com `
  --official-domain docs.99cdn.com `
  --style-domain zhihu.com `
  --output sources.jsonl
```

## 引用与版权

- 默认转述并链接原文，直接引用只取完成论证所需的短句。
- 不用一个作者的独特句式反复训练近似模仿，不要求“写得像某某作者”。
- 不抓取登录、付费或禁止访问内容，不绕过反爬、验证码和访问控制。
- 文章引用链接必须与附近声明相关；来源列表不能替代正文中的证据连接。
